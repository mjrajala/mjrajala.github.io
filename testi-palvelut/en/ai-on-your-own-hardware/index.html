Services / Private AI server

A private AI server: on your own hardware or operated by us.

An open language model can run on your own machine, or in a separate environment that we operate. Whichever you choose, the same things have to be agreed in writing: who owns it, where the machine is, what data leaves it and who applies the updates.

What we do

  • Sizing the model and the hardware

    We go through what the model is needed for and propose an open model that fits. The same review shows what kind of machine is enough, and which tasks don’t belong on a local model at all.

    • The use case reviewed before any hardware is bought
    • Model options and their limits on the same table
    • Hardware sizing: GPU, memory, disk
    • An assessment of which tasks are better done elsewhere

  • Setup and go-live

    We install the model into the chosen environment and make it usable in daily work. The interface and the API depend on who is going to use it.

    • Installation on your machine or in the agreed separate environment
    • A user interface for staff and an API for your own applications
    • Access rights, sign-in and logging switched on
    • Training and ready-made prompts for the agreed tasks

  • Upkeep to the agreed extent

    Upkeep is not one package but a list of items, each agreed separately. We write down which side is responsible for which.

    • Operating system and driver updates
    • Model updates and swaps as a separate decision
    • Monitoring and an alert when the server stops answering
    • The scope of backups, and one tested restore

Two delivery options

On your premises, or in a separate environment.

Both are scoped deliveries rather than service packages off a price list. The scoping happens before any hardware is bought or any environment is stood up.

If you have requirements about location, backups or access rights, we go through them during scoping and write them into the contract. We don’t decide them on your behalf.

A: On your premises, on your hardware

The machine is yours and it sits where you put it. We size it, install it and train your people, and upkeep is agreed separately.

Fits when you already have a server room and your own IT, or when the material must not travel over a network.

B: A separate environment operated by Aigen

The environment is reserved for you alone and we run it to the agreed extent. It is specified and procured as part of the project, so location, ownership and terms are agreed before go-live.

Fits when there is no server room of your own and you don’t want to build one, but you still want the model out of the general-purpose cloud services.

What gets agreed in either option

These seven points are reviewed during scoping and written into the contract. They are the same questions whichever option you pick. Only the answers differ.

Ownership

A: The machine is yours. You buy it, or we buy it in your name. Model files, configuration, the indexed material and the administrator accounts are yours.

B: The environment is reserved for you, but the owner of the machine or capacity and the contracting party are agreed at the start of the delivery. We also record who holds the material and what happens to it if the contract ends.

Location

A: The machine is in the room you put it in. The location is known to you and controlled by you.

B: The location is decided during scoping and written into the contract. We do not promise a particular country or data centre before it has been agreed and procured. If you have requirements about location, those are settled first.

What data leaves

A: When the processing is configured to stay fully local, the queries and the material stay on the machine. The only traffic out is what is opened deliberately: updates, remote support or chosen cloud connections.

B: The material travels to the environment over a network, so the transfer method, the encryption and the access are agreed separately. We record which data moves, where it is stored and for how long.

Backups

A: Backups are your responsibility unless agreed otherwise. We go through what is copied (configuration, index, material), where to and how often, and we test a restore once.

B: Backups are part of the scope: what is copied, where to, how often and how long it is kept. These are agreed case by case, not sold as a fixed package.

Updates

A: Operating system, driver and model updates are handled by your IT or by us to the agreed extent. Which one is written down.

B: We apply the updates. Change windows, and who approves a model swap, are agreed before go-live, and changes are announced in advance.

A model swap is always a separate decision, because the answers change with it. It doesn’t happen as a side effect of maintenance.

Access rights

A: The accounts are under your control. We agree whether we have administrative access, how it is opened and how it is logged.

B: Administrative access is ours and user access is yours. Administrative access is limited to named people and logged, and you can see the log.

External interfaces

A: The default is no outbound connections. If a task needs a cloud model or an external search, that is opened separately and only for that task.

B: The same choice is made separately. The environment can be fully closed, or it can use named external interfaces.

Cloud models such as Claude or ChatGPT do not run locally. They are reached through an API, and then the data you choose does leave. We record what.

What local execution does not solve

Your own server does not make an environment secure by itself.

A machine nobody patches is a risk regardless of whose building it stands in. Security and compliance come down to how access rights, logging, backups, contracts and personal data handling are arranged, and who has assessed them.

We don’t sell certifications, and a certification does not appear as a side effect of an installation. Regulated and classified environments are assessed separately against the requirements that apply to them, usually together with whoever owns security and legal on your side.

What we don’t promise

  • We don’t promise a response time, an availability figure or a service level before it has been agreed and written into a contract.
  • We don’t promise a particular country, data centre or capacity waiting on a shelf. The environment is specified and procured as part of the delivery.
  • We don’t publish a price in advance, because it depends on the hardware, the number of users and how far upkeep goes.
  • An open model running locally does not match the largest cloud models on every task. What is enough for you becomes clear once the tasks are reviewed.

When material cannot be sent outside

  • HR: internal questions and summaries of payroll and personnel data
  • Finance: going through unpublished forecasts, cash flow and acquisition calculations
  • Legal: searching and summarising confidential contracts and litigation material
  • Healthcare: summaries of patient records for a professional to check
  • R&D: search across your own technical documents and trade secrets
  • Defence: handling operational or technical documents in an isolated, approved environment

Decide before installation

  1. Which work the model is used for first.
  2. Which delivery option is chosen, and why.
  3. Which documents the model is given, and who approves them.
  4. Who maintains, updates and backs it up.

So what runs on the server?

A private server is a decision about where the model runs. The actual benefit comes from what gets built on top of it.

AI agents

The work should get done, not just explained. An agent does it and asks for approval.

Knowledge assistant

The answer is in some document and somebody needs it now, with the source.

Workflow automation

The same work is done every week and it should get done without the manual steps.

AI integrations

The data already sits in a system and it has to move between systems correctly.
