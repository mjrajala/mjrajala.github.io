AI agents: an assistant answers, an agent acts.

An assistant tells you how a purchase invoice gets matched. An agent matches it and hands you only the lines that didn’t match. We build agents that carry the work through inside your own systems, with the access rights they are given and no more.

The difference

Same subject, two different outcomes.

This isn’t a technical hair-split. It decides what the AI is allowed to touch and who answers for the result.

You ask an assistant

“What does the customer contract say about the notice period?”

The assistant finds the passage, shows it, and tells you which file it came from. After that, nothing has changed. You read the answer and decide what to do yourself.

An assistant writes nothing. The answer can still be wrong, though, and what the assistant can see has to be scoped deliberately.

You give an agent a task

“Go through yesterday’s requests for quotation and prepare the replies.”

The agent reads the messages, pulls products and prices from resource planning, drafts the replies and leaves them for you to approve. In the morning the work is done, and you decide what goes out.

An agent does things, so it has to be told what it may do and where it stops.

What we do

  • The agent’s task and its limits

    We start from one job that repeats for you. The agent gets that job in full — and only that job.

    • One job at a time, carried through to the end
    • Which data the agent may read, and from where
    • What it may not do without approval
    • Where it stops when data is missing or doesn’t match

  • Access rights like a new hire’s

    The agent gets its own account and the rights the task requires. If the task is preparing quotes, the agent sees the requests and the price list, not payroll.

    • Its own service account, never a person’s credentials
    • Named rights you can review and revoke
    • Access to the data the task needs, no wider
    • A log of what was done with that account and when

  • Approval at the agreed point

    A draft appears by itself. Sending, posting and paying do not, until that is separately agreed.

    • The agent prepares, a person approves
    • Exceptions to a person, routine through once trust is earned
    • A rejected draft comes back for correction instead of vanishing
    • Agreed in advance: who approves, and who covers for them

How much authority

The leash gets longer only once it has been earned.

Nobody hands a new hire the right to pay invoices unchecked on day one. An agent travels the same road, and moving from one level to the next is your decision.

An agent may stay permanently on the first or second level, and that is fine. The benefit comes from the work being prepared, not from removing the person.

  1. The agent preparesThe agent does the work and leaves everything for approval. You see what it did every single time. This is always where we start.
  2. The agent handles routineClear cases go through, exceptions come to you. The limits are agreed as numbers and conditions, not as a feeling.
  3. The agent acts aloneOnly where a mistake is cheap to undo and the log is easy to read. Plenty of jobs never reach this level.

Where we say no

  • An agent does not make decisions about a person on its own. Sorting applications against agreed criteria is fine; rejecting someone is not — that belongs to a human, and the EU AI Act sets its own requirements for this kind of use. See the AI Act guide.
  • An agent does not repair a broken process. Work that is unclear to a person is unclear to an agent.
  • An agent does not transfer responsibility. An entry is in your books even when the agent made it.

Where an agent is worth putting

A good first agent does the job nobody wants to do.

The best targets share a tell: the work repeats, it needs data from several places, and the result is something you can scan in a minute. Then the agent saves time immediately instead of demanding a month of learning.

We use agents in our own work every day, and we write on the blog about what has held up and what has not. That is the same experience we bring when we build one for you.

Examples worth starting from

  • A request for quotation arrives: the agent reads it, pulls products and prices, and drafts a reply for the salesperson to approve
  • Purchase invoices: the agent matches lines to the order and the delivery and raises only the exceptions
  • The weekly report: the agent collects the figures, writes the summary and flags what moved
  • Customer service: the agent finds the customer’s situation and has a draft reply waiting
  • A recurring reporting obligation: the agent assembles the material into the same template and says what is missing

Decide before building

  1. Which job the agent is given first.
  2. Which data and systems it gets access to.
  3. Where a person approves, and who that person is.
  4. Which level you start at, and what moving up would take.
  5. Where the agent runs: on top of an existing tool, or on your own server.
