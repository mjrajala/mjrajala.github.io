Services / Knowledge assistant

A knowledge assistant over your own documents.

The answer is in a contract, a work instruction or a two-year-old quote, but nobody remembers which file. A knowledge assistant retrieves it from your own material and shows the source beside the answer, so the answer can be checked.

What we do

  • Which material the assistant gets

    A good assistant comes from a bounded collection, not from the entire file server. We go through what is currently valid and who owns it.

    • One bounded collection at a time: work instructions, say, or contracts
    • Valid versions separated from superseded ones
    • File formats reviewed: PDF, Word, Excel, intranet, mail archive
    • Updates: a one-off run or continuous watching of a folder

  • The answer and its source

    The assistant is built to retrieve the answer from the material and show the source next to it. A language model can still assert something the source does not support, so the source is there to be checked, not as decoration.

    • Intended behaviour: the source file and passage shown beside the answer
    • Refusal criteria agreed: when the assistant answers “not found in the material” instead of guessing
    • Answers evaluated during go-live against your own questions, and the results reviewed with you
    • The assistant only reads; it writes to no system
    • Questions and answers are logged if that is what you want
    Blog: AI stopped being a search engine

  • Who sees what

    The assistant must not become a shortcut into material a user has no right to see. How far rights can be inherited depends on what the source system exposes. That is established before indexing and verified before go-live.

    • Rights inherited from the material as far as the source system allows
    • Where the system exposes no rights data, access is scoped with separate collections
    • Sign-in with your own accounts where an identity interface is available
    • HR and payroll material kept in its own collection or left out
    • The scoping verified with real user accounts before go-live

What the assistant can and cannot do

The assistant is a retrieval layer, not an expert.

The assistant finds and summarises what is in the material, and it does not fix the material. If the instruction in force is three years old, the assistant answers according to a three-year-old instruction and shows the source. That is why cleaning up and versioning the material belong inside the project, not on a list for afterwards.

The assistant is built to answer from the material, but a language model is not flawless about it: it can assert something the source does not support. So go-live includes a question set drawn from your own questions. We review the answers and their sources with you, agree when the assistant has to refuse, and repeat the same round whenever the material or the model changes.

Questions are worth keeping within what the material can support. “What does the contract say about limitation of liability” is a good question. “Should we sign this contract” is not, because the answer isn’t in the material. During go-live we go through which kinds of question the assistant answers reliably and which belong to a person.

What the assistant does not do

  • It does not replace a lawyer, an accountant or a specialist. An answer is a starting point, not a decision.
  • It is not flawless. The model can assert something the source does not support, so an answer that matters gets checked against the source.
  • It does not fill in material you don’t have. No document, no reliable answer.
  • It does not calculate reliably. Figures and calculations are checked against the source.
  • It does not write anything into a system. That needs an integration or an automation.

Examples of collections worth starting from

  • Work instructions and the quality manual, when the shop floor asks the same thing every week
  • Current customer and supplier contracts and their terms
  • Onboarding material, so a new hire asks the assistant before asking a colleague
  • Earlier quotes and tender responses, when a new one has to be written
  • Product documentation and technical instructions, as backup for customer service

Decide before go-live

  1. Which collection is indexed first and who approves its contents.
  2. Who sees what, and which material is left out entirely.
  3. Whether the source system exposes access rights, or access is scoped with separate collections.
  4. How often the material changes and who is responsible for it.
  5. Where the model runs: on your own server or through an interface.
